# Соглашения по коду (GDScript, Godot 4)

## Общее
- Следовать официальному GDScript style guide той версии Godot, что указана в `CLAUDE.md` §6.
- **Статическая типизация везде:** `var x: int`, `var a := 1`, типы аргументов и возврата у всех функций,
  типизированные массивы (`Array[int]`). Untyped — только если API движка иначе не позволяет.
- Отступ — табы (стандарт Godot), LF, финальный перевод строки.

## Именование
- Файлы и папки — `snake_case` (`island_generator.gd`, `main.tscn`).
- `class_name` — `PascalCase`; для глобальных классов `sim/` — с осмысленным именем, не конфликтующим со встроенными
  классами Godot (поэтому `VgiRng`, а не `Rng`).
- Функции и переменные — `snake_case`, константы — `UPPER_SNAKE`, сигналы — `snake_case` в прошедшем времени
  (`item_grabbed`), приватное — с префиксом `_`.
- Узлы в сценах — `PascalCase` (`Hand`, `CameraRig`).

## Порядок в скрипте
`class_name` → `extends` → doc-комментарий `##` → сигналы → enum → константы → `@export` → публичные переменные →
приватные переменные → `@onready` → встроенные колбэки (`_ready`, `_process`…) → публичные методы → приватные.

## Комментарии
- На русском, кратко, объясняют «почему». Doc-комментарии `##` для публичных классов и функций.
- `TODO` только с номером этапа: `# TODO этап 2: ...`.
- Магические числа баланса — именованными константами в начале модуля (позже — отдельный ресурс баланса).

## sim/
- Только `static func` над данными мира или `RefCounted`-классы без связи со сценой.
- Запрещено: см. `CLAUDE.md` §2 (`randf`, `Time`, `Node`, физика движка и т.д.), а также `print` в рабочем коде.
- Порядок итерации детерминирован: обходить массивы или отсортированные ключи, не полагаться на порядок
  вставки в `Dictionary`, если ключи добавляются в разном порядке.
- Целочисленная арифметика с переполнением (RNG) — с явной маской `& 0xFFFFFFFF`.

## game/
- Не содержит игровых правил — только отображение, ввод, звук, эффекты.
- Связь узлов: вниз — вызовами методов, вверх — сигналами. Без длинных путей `get_node("../../..")`.
- Сцена = переиспользуемая единица (рука, предмет, человечек — отдельные `.tscn`).
- Ресурсы, создаваемые в коде в цикле, переиспользовать; тяжёлые ресурсы — `preload`.

## Тесты
- GUT, файлы `tests/test_*.gd`, класс `extends GutTest`, функции `test_*`. Названия — по-английски в `snake_case`,
  описание поведения можно дублировать комментарием на русском.
- Обязательные виды тестов для `sim/`:
  - совпадение с эталоном `tests/fixtures/ts_reference.json` (пока он актуален);
  - детерминизм (одинаковый seed → одинаковый результат);
  - эквивалентность `catch_up` и живых тиков при изменении `step`;
  - баланс-гарды (например: человечек переживает сутки офлайна);
  - инварианты генерации (все биомы на 200 seed'ах).
- Тест бага: сначала воспроизвести (красный), потом исправить.
