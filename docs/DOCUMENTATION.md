# Правила документации

Документация — часть изменения, а не отдельная задача. Устаревшая документация хуже отсутствующей.

## Что и когда обновлять

| Изменение | Обновить |
|---|---|
| Любое пользовательски значимое изменение (фича, фикс, баланс, сброс сейвов) | `CHANGELOG.md` → `[Unreleased]` |
| Сдвинулся статус этапа, новый «следующий шаг», найдена/закрыта известная проблема | `docs/ROADMAP.md` |
| Изменилась механика, правило игры, визуальный стиль | `docs/GAME_DESIGN.md` |
| Изменилась структура модулей, поток данных, формат сейва | `docs/ARCHITECTURE.md` |
| Принято решение с альтернативами (библиотека, протокол, формат, отказ от идеи) | новый ADR в `docs/decisions/` |
| Новые команды, требования к окружению | `README.md` и `CLAUDE.md` §6 |
| Новое правило работы для AI | `CLAUDE.md` |

Чисто внутренний рефакторинг без изменения поведения — в CHANGELOG можно не писать.

## CHANGELOG.md
- Формат [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), разделы: `Added`, `Changed`, `Fixed`, `Removed`, `Docs`.
- Новые записи — в `[Unreleased]`. Одна строка = одно изменение, на русском, с префиксом пакета: `sim:`, `client:`, `server:`, `repo:`.
- При завершении этапа roadmap секция `[Unreleased]` переименовывается в `[0.N.0] — ГГГГ-ММ-ДД — Этап N: название`,
  и создаётся новая пустая `[Unreleased]`. Версия `0.N` = номер завершённого этапа.
- Ломающие изменения (сброс сейвов, смена формата) помечать **BREAKING**.

## ADR (Architecture Decision Records)
- Папка `docs/decisions/`, файлы `NNNN-kebab-case.md`, номер по порядку, шаблон — `0000-template.md`.
- ADR не редактируют задним числом по смыслу. Если решение меняется — новый ADR со статусом
  «Принято», а у старого статус меняется на «Заменено ADR-NNNN».
- Индекс ADR — `docs/decisions/README.md`, обновлять при добавлении.

## ROADMAP.md
- Статусы: `—` не начат, `⏳ в работе` (с перечнем сделанного), `✅ готово`.
- Раздел «Следующий шаг» всегда актуален — это точка входа для следующей сессии.
- Раздел «Известное» — временные решения, долги, непроверенные вещи.

## Стиль текста
- Русский язык, коротко, списками и таблицами. Без воды и маркетинга.
- Имена файлов, функций, команд — в `обратных кавычках`.
- Не дублировать: если правило описано в одном файле, в другом — ссылка.
- Писать только то, что правда для текущего кода. Планы явно помечать как план.
