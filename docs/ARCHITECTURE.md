# Архитектура

> Описывает **текущее** состояние кода. При изменении структуры — обновлять в том же коммите.

## Пакеты

```
packages/
  sim/      @vgi/sim     — чистая логика: генерация острова, мир, тик. Без рендера и I/O.
  client/   @vgi/client  — браузер: Three.js-сцена, ввод, HUD, сейв в localStorage.
  server/   @vgi/server  — заглушка, NestJS на этапе 6.
```

Зависимости строго в одну сторону: `client → sim`, `server → sim`. `sim` не импортирует ничего из других пакетов.
`@vgi/sim` экспортирует исходники TS напрямую (`"exports": "./src/index.ts"`), отдельной сборки нет.

## sim

| Модуль | Ответственность |
|---|---|
| `rng.ts` | mulberry32. `nextFloat(holder)` — состояние в `World.rngState` (сериализуется). `createRng(seed)` — для генерации. |
| `noise.ts` | Value noise на сетке, без зависимостей. |
| `generate.ts` | `generateIsland(seed, size)` → `IslandMap` (биомы + высоты). Гарантирует наличие всех биомов. |
| `engine.ts` | `World`, `createWorld`, `step` (1 тик), `catchUp` (догонка по реальному времени). |

### Инварианты
1. **Детерминизм:** одинаковый `World` + одинаковые действия → одинаковый результат на любой машине.
   Это основа офлайн-догонки и будущей серверной валидации реплеем.
2. `step(world)` не читает время и внешнее состояние. Реальное время — только `catchUp(world, now)`.
3. `catchUp` ≡ N вызовов `step` (покрыто тестом). Максимум — `MAX_OFFLINE_TICKS` (сутки).
4. Карта острова не хранится в `World`: она воспроизводится из `world.seed` через `generateIsland`.
   Когда появятся изменения ландшафта (кратеры), в `World` хранится только **дельта** относительно сгенерированной карты.
5. `World` — JSON-совместимые данные.

### Время
- 1 тик = 1 реальная минута (`TICK_MS`).
- `lastSeen` сдвигается ровно на прогнанные тики — неполный тик не теряется.

## client

| Модуль | Ответственность |
|---|---|
| `main.ts` | Сборка сцены, камера (OrbitControls), цикл рендера, раз в секунду `catchUp` + сейв + HUD. |
| `terrain.ts` | Меш острова из `IslandMap` (vertex colors, flatShading), плоскость воды. |
| `hand.ts` | Рука бога (сейчас сфера-заглушка), следование за курсором через raycast. |
| `save.ts` | Загрузка/сохранение `World` в `localStorage`. Единственное место с `Math.random()` (выбор seed). |

Поток данных: `localStorage → World → catchUp → (рендер читает World) → saveWorld`.
Ввод игрока в будущем превращается в **действия** (`applyAction(world, action)` в sim), а не в прямую мутацию `World` из client.

## Сейвы
- Ключ: `vgi:save:v1` (`client/src/save.ts`).
- Любое несовместимое изменение формы `World` требует: либо миграции `vN → vN+1` (предпочтительно, с тестом),
  либо смены ключа с записью в `CHANGELOG.md` о сбросе сейвов.

## server (план, этап 6)
NestJS, использует тот же `@vgi/sim`. Клиент шлёт seed + лог действий, сервер прогоняет реплей и сверяет.
Сервер владеет только тем, что передаётся между игроками. См. `GAME_DESIGN.md` → «Мультиплеер».
