# Virtual God Island — инструкции для Claude

Перед работой прочитай `docs/GAME_DESIGN.md` (концепт, механики, решения) и `docs/ROADMAP.md` (этапы, текущий статус).

## Формат ответов
- Кратко, конкретно, технически точно. Сначала решение, потом короткое объяснение.
- Изменения — по файлам, только изменённые фрагменты, если весь файл не нужен.
- Всегда шаг проверки (команда). Не выдумывать API библиотек; если не уверен — проверить или сказать.
- Ответы на русском.

## Архитектура (не нарушать)
- Монорепо pnpm: `packages/sim` (логика), `packages/client` (Three.js), `packages/server` (NestJS, этап 6).
- `sim/` детерминирован и не зависит от рендера: никаких `Math.random()`, `Date.now()`, DOM, three внутри.
  Случайность — `nextFloat(world)` / `createRng(seed)`. Реальное время — только в `catchUp(world, now)`.
- Каждая механика: сначала `sim/` + тест (vitest), потом визуал в `client/`.
- Состояние `World` должно сериализоваться в JSON (сейв в localStorage, позже — валидация на сервере реплеем).
- Новые зависимости — только при необходимости, версии пинить точно.

