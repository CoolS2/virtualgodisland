# Virtual God Island — инструкции для AI-агента

Этот файл — главный свод правил для любого AI-ассистента (Claude Code и др.), работающего в репозитории.
`AGENTS.md` ссылается сюда. При конфликте правил приоритет: прямое указание пользователя → этот файл → `docs/*`.

> Движок — Godot 4 (ADR-0005). Прототип на TypeScript + Three.js удалён; он есть в истории git
> (последний коммит с ним — `0d0764a`), его поведение зафиксировано в `tests/fixtures/ts_reference.json`.

## 0. С чего начать каждую сессию
1. Прочитать `docs/ROADMAP.md` — текущий этап, раздел «Следующий шаг», «Известное».
2. Прочитать `docs/GAME_DESIGN.md` — концепт и уже принятые решения по игре.
3. Просмотреть `CHANGELOG.md` (раздел `[Unreleased]`) и `docs/decisions/` — что сделано и почему.
4. По коду задачи — `docs/ARCHITECTURE.md` и `docs/CONVENTIONS.md`.
5. `git log --oneline -20` — последние изменения.
6. Проверить, что Godot доступен (`godot --version`). Если нет — сказать об этом, а не писать код вслепую.

## 1. Честность и формат ответов
- **Только правда.** Если не уверен — сказать «не уверен» сразу и предложить способ проверить. Не выдумывать API,
  версии, результаты команд. API Godot проверять по документации **той версии**, что указана в §6
  (API Godot 3 и Godot 4 сильно различаются — не путать).
- Не писать «проверено/работает», если команда не запускалась. Визуальное поведение без запуска/скриншота
  помечать как «не проверено визуально».
- Ответы — на русском, кратко и технически точно: сначала решение, потом короткое объяснение.
- Всегда давать шаг проверки (команду).
- Спорные дизайнерские решения (механика, баланс, стиль) — не принимать молча: предложить вариант и спросить.

## 2. Архитектура (не нарушать)
Подробно — `docs/ARCHITECTURE.md`.
- Движок Godot 4, язык GDScript, статическая типизация обязательна.
- `sim/` — детерминированная логика мира, не зависит от сцены и рендера. В `sim/` **запрещены**:
  `randf()`, `randi()`, `RandomNumberGenerator` без явного seed, `Time.*`, `OS.get_ticks_*`, доступ к `SceneTree`,
  `Node`, `get_node`, `Engine`, файлам, сигналам движка, встроенной физике.
  Случайность — собственный RNG `VgiRng` (mulberry32). Реальное время — только в `WorldEngine.catch_up(world, now_ms)`.
- Состояние мира — сериализуемые данные (Dictionary/Array/int/float/String/bool), сохраняются в JSON.
- Каждая механика: сначала `sim/` + тест (GUT), потом сцена/визуал в `game/`.
- `game/` читает состояние `sim/` и отправляет в него действия; игровые правила в `game/` не пишутся.
- Встроенная физика Godot — только для визуальных эффектов, не для состояния мира.
- Изменение формы сохраняемого мира = изменение формата сейва → версия сейва + миграция (см. ARCHITECTURE).

## 3. Рабочий цикл задачи
1. Понять задачу; при неоднозначности — уточнить. Крупную задачу разбить на шаги.
2. Реализовать минимально нужное. Не делать рефакторинг «заодно» без запроса.
3. Тесты: новая логика в `sim/` → новый тест. Исправление бага → тест, который падал до исправления.
4. Проверка: запуск тестов headless (§6) + импорт проекта без ошибок; при изменении сцен — запуск/скриншот.
5. Документация — по `docs/DOCUMENTATION.md` (минимум: `CHANGELOG.md` → `[Unreleased]`, статус в `ROADMAP.md`).
6. Коммит по правилам ниже. Push — в назначенную ветку.

### Definition of Done
- [ ] Тесты GUT зелёные, проект импортируется без ошибок и предупреждений парсера (результат реально получен).
- [ ] Для новой логики `sim/` есть тесты, в т.ч. на детерминизм, если затронуты RNG/тик.
- [ ] `CHANGELOG.md` обновлён.
- [ ] `ROADMAP.md` обновлён, если сдвинулся статус этапа / «Следующий шаг» / «Известное».
- [ ] `GAME_DESIGN.md` обновлён, если изменилась механика или правило игры.
- [ ] ADR в `docs/decisions/`, если принято архитектурное решение (аддон, формат данных, протокол).
- [ ] Нет мёртвого кода, отладочных `print`, закомментированных блоков.

## 4. Git
- Conventional Commits на английском: `feat(sim): ...`, `fix(game): ...`, `docs: ...`, `test(sim): ...`,
  `chore: ...`, `refactor(...)`, `perf(...)`. Тело — по желанию, «что и зачем».
- Один коммит — одно логическое изменение. Документация может идти в том же коммите, что и код.
- Не коммитить: `.godot/` (кэш импорта), сборки (`build/`), сейвы, секреты, `.env`.
- Коммитить: `project.godot`, `*.tscn`, `*.tres`, `*.gd`, `*.gd.uid`, `*.import` (метаданные импорта ассетов), `export_presets.cfg`
  (без паролей/ключей подписи).
- Не переписывать опубликованную историю; не делать `push --force` без явного разрешения.
- PR создавать только по просьбе пользователя (шаблон — `.github/pull_request_template.md`).

## 5. Зависимости и ассеты
- Аддоны (в `addons/`) — только при реальной необходимости, с обоснованием (ADR для значимых), версия фиксируется
  в `docs/ASSETS.md`. Перед добавлением проверить актуальную версию и совместимость с нашей версией Godot.
- `sim/` — без аддонов.
- Ассеты — только с лицензией, разрешающей коммерческое использование (CC0 предпочтительно); источник, автор
  и лицензия каждого — в `docs/ASSETS.md`.
- Версия Godot меняется только осознанно: запись в CHANGELOG, обновление §6 и CI.

## 6. Команды
Версия Godot: **4.7.2-stable** (рендерер Compatibility — нужен для Web). GUT: **9.7.1** (`docs/ASSETS.md`).
```bash
godot --version                                              # проверить версию
godot --headless --path . --import                           # импорт проекта (ошибки парсера видны в выводе)
godot --headless --path . -s addons/gut/gut_cmdln.gd -gexit  # тесты GUT (настройки — .gutconfig.json)
godot --path .                                               # запустить игру
```
CI (`.github/workflows/ci.yml`) запускает импорт и тесты на официальной сборке той же версии.
Если локально Godot нет — проверять через CI и прямо говорить, что локально не запускалось.
